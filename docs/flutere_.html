What OCR Extracts from Label
🔢
SKU — alphanumeric product code, matched against orders.product_manifest[].sku
📊
Barcode (EAN-13/QR) — cross-checked with product catalogue in local SQLite cache
📝
Product Name — NLP token match as secondary confirm layer
⚖
Weight printed on label — compared to expected weight for pre-check before scale
📅
Expiry Date — extracted and logged; flag if within 14 days

Weight Outcome Rules
✅
PASS (delta ≤ ±50g) — Proceed to RFID write. Green overlay.
⚠
WARN (±50–150g) — Supervisor PIN required to proceed. Logged as exception.
🚨
FAIL (>150g) — Hard block. Must recheck products, re-scan, re-weigh. Cannot proceed.
🔵
No BLE Scale — Manual entry mode; weight typed and flagged as manual in audit log. NFC tag unchanged.

SCREEN 06
RFID Write, Encrypt & Sector Lock
06 / 09
📡
NFC Tag Write — Manifest Hash + AES-128 Sector Lock
/pack/:orderId/nfc-write
Only available after all three verifications pass. Worker taps the phone's NFC reader directly onto the NXP NTAG 424 DNA / ICODE SLIX2 tag embedded in the box lid. App uses flutter_nfc_kit to write the order manifest SHA-256 hash + order metadata to tag memory pages. All write pages are locked with AES-128 password. Kill password stored encrypted in Supabase vault. After write, lock state is verified with a read-back check — all within the same NFC session.

NFC Write Flow
1
Enable NFC Session
FlutterNfcKit.poll() — app waits for tag. Worker taps phone to box lid. ISO 15693 / ISO 14443 discovery.
2
Fetch Write Payload
GET /api/nfc/write-payload/{orderId} — server returns AES-128 encrypted page data. Key never stored on device.
3
Write Pages 1–3
Sequential NDEF / raw page write with read-back verify after each page. Mismatch → retry ×3 → alert.
4
Password Lock
POST /api/nfc/lock with box_id. Server returns PWD_AUTH0 payload. App writes to tag access config page.
5
Verify Lock State
Attempt write without password → should return AUTH_ERROR (confirm lock active).
6
Confirm to Backend
POST lock confirmation. Supabase smart_boxes.status updated to packed. NFC session closed.

APPENDIX B
Offline Mode & Sync Strategy
What Works Offline
✅
OCR label scan — on-device google_ml_kit; no network needed
✅
NFC write & lock — AES key cached securely; works without server if payload pre-fetched
✅
Weight check — BLE scale read is local; result stored in Drift SQLite
✅
Seal photo capture — stored locally; synced when online
✅
TFLite vision check — on-device model; no cloud needed
⚠
Hub gate scan display — MQTT events buffered in local DB; real-time lost but catches up on reconnect
✗
Cloud Vision API — requires internet; falls back to TFLite offline model automatically
Sync Strategy (Drift + Supabase)
1
Write to Drift (local SQLite) first
Every action saves locally. App works without network. Timestamp + synced = false flag.
2
Background sync on network restore
Connectivity plugin fires. Queue of synced=false rows uploaded to Supabase in order.
3
Conflict resolution
Server timestamp wins. Any conflict logged to sync_conflicts table for supervisor review.
4
Incremental order prefetch
On app open with network: pull next 24h orders into local cache for full offline operation.
